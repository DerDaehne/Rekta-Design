roots

Inspired by Metro.

Rekta Design is inspired by Microsoft's Metro design language, to us one of the best UX designs ever shipped, from Zune and Windows Phone 7 (2010) to Windows 8 (2012). We find it a pity that no major product uses it today, so Rekta Design takes up its ideas in its own form: its own tokens, typography and components.

  1. 2000sMedia Center, Zune
  2. 2010Windows Phone 7
  3. 2012Windows 8
  4. todayinspired: Rekta Design
  • content over chromeThe information is the interface. Nothing gets a box just to look tidy.
  • authentically digitalNo imitation leather or paper: type, colour and motion that belong to a screen.
  • type as structureRooted in the Swiss International Typographic Style and in the wayfinding signage of public transport: large, plain, readable at a glance.

Its token values are derived from the source code of the Porsche Design System (Apache-2.0): numbers and colours only, no code, fonts or marks.

sources: Metro (design language) · International Typographic Style · Porsche Design System

principles

Nothing is decoration.

  1. content over chromeNo cards, no boxed panels. Information sits on the ground, grouped by hairlines and whitespace.
  2. motion as guidanceEvery transition answers a question: where am I, which facet, what just happened.
  3. information-dense live tilesA tile's size follows importance; its fill colour is its status.
  4. panorama and pivotOne place, wider than the screen, moved through sideways; its facets in a fixed order.
  5. refined precisionHairlines, tabular figures, calm large areas, vivid small accents.

colour

Status is a fill, not an accent.

Neutral ground, no brand hue. Four status colours carry meaning and only meaning: large fills use the dampened tile form, small marks the saturated full form. Primary text sits on every fill and must clear AA; the ratios are measured live in the current theme.

tiles

Tiles, not cards.

A tile's whole area is one fill, and the fill is its status. Size follows importance. Content follows a few patterns: stat pair, sparkline, progress, status word. Click a tile to change its status. The data is invented and updates live.

Finished tiles drop their sparkline: stillness means done. Every chart has a text equivalent for screen readers.

panorama & pivot

One place, wider than the screen.

A panorama is one place laid out sideways. On desktop a plain mouse wheel moves it sideways, except where something can still scroll vertically; horizontal input is left alone, and at either end the wheel falls through. Below {{breakpoint.sideways-scroll-min}} everything stacks vertically.

A pivot is one place's facets in a fixed order. The active title is large; the strip scrolls so it sits at the left edge, never reordered. Try it:

accessibility

Checked, not assumed.

  • keyboard firstTab through the pivot, focus the panorama and use ← →, change tiles with Enter.
  • focus on fillsThe ring is drawn inset in the current text colour, so it survives every status fill. Tab into the tiles below.
  • colour is never the only signalEvery tile spells out its status; every chart has a text equivalent.
  • contrast is measuredPrimary text clears AA on every fill in both themes, enforced by build-css.mjs --check.
  • reduced motionFollows the system setting and the switch in the app bar.
  • 44px targetsEvery control in the app bar is at least 44 × 44px.

platforms

Same numbers, different plumbing.

The tokens are platform-neutral. Only units and OS integration points differ between the web and a native desktop app.

conceptwebnative desktop
unitsCSS px; fluid sizes as clamp() against vwlogical pixels; interpolate the same min/preferred/max triple against window width
breakpointsmedia queries on viewport widthwindow-size classes at the same thresholds, never monitor size
sideways wheelvertical wheel delta redirected on the panoramanative wheel event, same rule; trackpad pans left alone
keyboardDOM key events, :focus-visiblenative focus traversal; same behaviours
reduced motionprefers-reduced-motion plus data-motion="off"the OS setting plus the same in-app switch; durations become 0
themeprefers-color-scheme plus data-themethe OS appearance plus an in-app switch; two independent token sets
focus ringsinset outline in currentColornative focus drawing, same rule: text colour, inset

get started

Tokens first, CSS on the web.

  1. take the tokensrekta.tokens.json holds every value in W3C Design Tokens (DTCG) format. Native apps read it directly.
  2. build the CSSOr download rekta.css. 
    node scripts/build-css.mjs          # writes dist/rekta.css
node scripts/build-css.mjs --check  # tokens present, AA on every fill
  3. use the variables 
    <link rel="stylesheet" href="rekta.css">

.tile {
  background: var(--rekta-color-status-info-tile);
  color: var(--rekta-color-text-primary);
  border-radius: var(--rekta-radius-tile);
}
  4. pick a themeLight and dark follow the system; data-theme="dark" on the root forces one, data-motion="off" turns motion off.
